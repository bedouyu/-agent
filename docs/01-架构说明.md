# 架构说明

## 当前最小闭环

```text
WPF 界面
  → PaperProjectApiClient（发送 HTTP 请求）
  → Controller（接收项目和文档请求）
  → Service（执行业务规则）
  → Repository（读写数据库元数据）
  → H2 文件数据库

文档上传还会经过：

```text
PaperDocumentService
  → DocumentStorageService（校验并保存 ZIP、TEX 或 DOCX）
  → data/documents（保存原始文件）
```
```

每一层只负责一件事：

- `Controller`：HTTP 地址、参数校验、状态码。
- `Service`：业务规则和事务。
- `Repository`：数据库访问。
- `Entity`：数据库中的项目和文档元数据结构。
- `Response/Request`：前后端传输的数据结构。
- `ViewModel`：Windows 界面的状态和操作。
- `ApiClient`：封装后端接口调用。

## 为什么使用 H2

当前是本机单人应用，H2 可以把数据库保存为项目目录中的文件，不需要安装数据库服务，也不需要 Docker。以后如果需要多人使用，再把数据访问配置切换为 MySQL。

## 后续模块

建议按顺序增加：

1. LaTeX 工程 ZIP、单 TEX、DOCX 上传与原始文件保存（已完成）。
2. LaTeX 源码读取和版本管理。
3. LaTeX 文档结构、命令、环境和引用解析。
4. 确定性的 LaTeX 格式规则检查。
5. 大模型配置与密钥安全存储。
6. 源码修改建议及差异接受/拒绝流程。
7. 生成新版本 `.tex`，以后再扩展 PDF 编译。

## LaTeX 修改原则

- `source.tex` 始终作为只读原稿保存。
- 每次 Agent 修改生成新的版本文件，不覆盖原稿。
- 界面先展示源码差异，用户确认后再设为当前版本。
- 第一版只接受 UTF-8 编码，避免中文编码转换造成内容损坏。
- 多文件论文以 ZIP 导入，必须包含 `main.tex`；后端保留原始 ZIP，并安全展开到独立工作区。

## 真实样例带来的设计约束

参考 `D:\desktop\投稿(1)\投稿` 中的论文工程，当前需要覆盖：

- 使用 XeLaTeX 和 `ctexart` 的中文论文。
- `main.tex` 通过多层 `\input` 引入正文、预备知识、附录和参考文献。
- 字体设置可能依赖 SimSun、SimHei、KaiTi 和 FangSong 等 Windows 字体。
- 工程目录中会混有 `.aux`、`.log`、`.out`、`.toc`、`.xdv`、`.synctex.gz` 等编译产物。
- 格式检查只扫描源码与资源文件；编译产物不应发送给大模型，也不作为可修改源码。

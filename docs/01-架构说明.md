# 架构说明

## 当前最小闭环

```text
WPF 界面
  → PaperProjectApiClient（发送 HTTP 请求）
  → Controller（接收项目和文档请求）
  → Service（执行业务规则）
  → Repository（读写数据库元数据）
  → H2 文件数据库
```

文档上传与 LaTeX 编译还会经过：

```text
PaperDocumentService
  → DocumentStorageService（校验并保存 ZIP、TEX 或 DOCX）
  → data/documents（保存原始文件）

PaperDocumentService
  → LatexCompileService
      → latexmk + XeLaTeX（生成 PDF 和 .synctex.gz）
      → TeX Live rungs/Ghostscript（把 PDF 渲染成 PNG 页面）
      → synctex edit（PDF 坐标反向定位源码）

手动生成多 Agent 建议还会经过：

WPF（选中源码、二次确认）
  → AiController
  → PaperDocumentService（确认选区来自当前源文件）
  → AgentOrchestrator（按顺序运行专职 Agent）
      → LatexEditAgent → DeepSeekService（生成候选建议）
      → LatexReviewAgent → LatexSafetyGuard（本地检查）
                         → DeepSeekService（安全检查通过时再调用模型复核）
  → WPF（展示原文、建议、审查结果和步骤）
```

每一层只负责一件事：

- `Controller`：HTTP 地址、参数校验、状态码。
- `Service`：业务规则和事务。
- `Repository`：数据库访问。
- `Entity`：数据库中的项目和文档元数据结构。
- `Response/Request`：前后端传输的数据结构。
- `ViewModel`：Windows 界面的状态和操作。
- `ApiClient`：封装后端接口调用。
- `LatexCompileService`：只负责调用 TeX Live 工具和解析结果，不处理界面状态。
- `DeepSeekService`：只处理用户确认的片段，不将密钥、请求正文或回复写入数据库或日志。
- `AiModelGateway`：模型通信接口；两个 Agent 不依赖具体的 HTTP 或 Spring AI 实现。
- `AgentOrchestrator`：负责执行顺序；不直接调用模型或修改论文文件。
- `PaperAgent`：专职 Agent 接口；新 Agent 可通过 Spring 注册并指定 `@Order`。
- `LatexSafetyGuard`：检查明显的 LaTeX 结构风险；不是完整语法分析或编译验证。

当前是两个 Agent 的有序协作，不是自动重试循环。审查 Agent 的模型判断只是辅助意见；没有自动写回、版本接受或候选编译。每次请求创建独立 `AgentContext`，不持久化论文内容或模型消息。未来加入版本与编译循环时，应由编排层强制执行次数、范围和人工确认限制。

扩展方法：新建实现 `PaperAgent` 的 Spring 组件，用 `@Order` 指定它在编辑、审查前后的位置；仅在适用时让 `supports` 返回 `true`。需要更换模型框架时，实现 `AiModelGateway`，无需修改各个 Agent。当前默认只有 `DeepSeekService` 一个网关实现。

## 点击 PDF 跳转源码的流程

```text
用户单击应用内 PDF 页面
  → WPF 将图片像素坐标换算为 PDF point 坐标
  → GET /synctex?page=...&x=...&y=...
  → Java 执行 synctex edit
  → 返回 sourcePath + line + column
  → WPF 读取对应 .tex 并滚动、选中该行
```

PDF 预览使用页面图片而不是嵌入浏览器，原因是本机无需安装 WebView2 或第三方 PDF 控件，依赖更少，也更容易准确取得点击坐标。

## 为什么使用 H2

当前是本机单人应用，H2 可以把数据库保存为项目目录中的文件，不需要安装数据库服务，也不需要 Docker。以后如果需要多人使用，再把数据访问配置切换为 MySQL。

## LaTeX 修改原则

- `source.tex` 始终作为只读原稿保存。
- 每次 Agent 修改生成新的版本文件，不覆盖原稿。
- 界面先展示源码差异，用户确认后再设为当前版本。
- 第一版只接受 UTF-8 编码，避免中文编码转换造成内容损坏。
- 多文件论文以 ZIP 导入，必须包含 `main.tex`；后端保留原始 ZIP，并安全展开到独立工作区。

## 真实样例带来的设计约束

根据实际中文论文工程样例，当前需要覆盖：

- 使用 XeLaTeX 和 `ctexart` 的中文论文。
- `main.tex` 通过多层 `\input` 引入正文、预备知识、附录和参考文献。
- 字体设置可能依赖 SimSun、SimHei、KaiTi 和 FangSong 等 Windows 字体。
- 工程目录中会混有 `.aux`、`.log`、`.out`、`.toc`、`.xdv`、`.synctex.gz` 等编译产物。
- 格式检查只扫描源码与资源文件；编译产物不应发送给大模型，也不作为可修改源码。
